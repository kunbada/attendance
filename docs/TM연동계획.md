# TM 앱 + KT 통화매니저 연동 계획 (초안, 2026-11-11)

> **이 문서의 상태**: 초안. KT 의 **공식 개발 문서는 아직 보지 못했다.** 2-1 장은 인터넷에 공개된 다른 업체들의 안내문에서 확인한 내용이고(공식 문서 아님, 일부는 2021~22년 기준), 그 밖의 KT API 내용은 **가정**이다.
> 아래 2장의 "확인할 것"을 먼저 채운 뒤 4장의 방식을 확정한다.
> 다음 작업자(다른 모델 포함)는 `CLAUDE.md`(루트) → `docs/통합구성안.md` → 이 문서 순으로 읽고 시작한다.

## 1. 목표
- TM 담당자가 통합 서버의 **고객 DB**(고객관리 > 고객 DB)에서 배정받은 고객에게 전화를 걸고, 결과를 바로 남기는 **TM 앱**(`web/tm/`)을 만든다.
- KT 통화매니저와 연동해 ① 화면에서 눌러 전화 걸기 ② 통화 이력(발신·수신·부재·통화 시간)을 고객 이력에 자동 기록 ③ (가능하면) 걸려 온 전화의 고객 정보 띄우기 ④ (가능하면) 녹취 연결.
- 새 고객 원장은 만들지 않는다. **이미 있는 표를 그대로 쓴다.**

## 2-1. 조사해서 알게 된 것 (2026-11-11, 공식 문서 아님 — KT 에 다시 확인할 것)
- **상품 이름**: KT 부가서비스 **"통화매니저 API(형)"** (CID API). 일반 "통화매니저" 가입만으로는 연동이 안 되는 것으로 보인다.
- **가입 창구**: KT 지능망센터 **080-001-1588** 에 전화로 신청. 신청할 때 **CP코드(연동 프로그램을 만든 회사 번호)와 솔루션 코드(보통 01)** 를 말해야 한다.
  - CP코드는 프로그램 회사마다 다르다 (예: 병원·매장용 프로그램 회사들이 각자 7xxxx 번호를 갖고 있음). → **우리가 직접 연동하려면 위뉴(또는 개발 주체)가 KT 에 개발사(CP사)로 등록해 CP코드를 받아야 한다.** 등록 절차·조건·기간은 확인하지 못했다. 문의처 후보: 080-001-1588, KT API Link(`apilink.kt.co.kr`).
- **요금(회선당, 통신사에 납부)**: 일반 유선전화 월 4,400원, 인터넷전화는 **센트릭스 회선만 가능**하고 월 5,500원 (2021~22년 안내 기준, 바뀌었을 수 있음).
- **다른 업체 프로그램에서 확인되는 기능**: 전화가 오면 발신 번호 알림(수신 팝업), 부재중 전화 확인, 문자 수신, **프로그램에서 눌러 전화 걸기**.
- **로그인**: 통화매니저 아이디·비밀번호 (가입 때 만든 관리자 아이디, 보통 `전화번호@kt.com` 형식). **회선 하나에 아이디는 관리자 포함 최대 4개**, 아이디마다 다른 PC 에서 로그인.
- **확인하지 못한 것 (T0 에서 반드시 확인)**: ① 서버(Cloudflare Worker)에서 부를 수 있는지, 아니면 PC 프로그램/브라우저에서만 되는지 ② 통화 이력(통화 시간·결과) 조회 API ③ 녹취 파일 조회 ④ 호출 한도·IP 제한 ⑤ CP사 등록 조건과 비용(수익 배분 구조가 있다는 2012년 기사 있음).
- **판단**: CP사 등록이 어렵거나 오래 걸리면 4장의 **C 방식(API 없이)** 으로 먼저 쓰고, 등록이 되면 A/B 를 붙인다. 이미 CP코드를 가진 다른 업체 프로그램과 연결하는 방법도 있으나 그 업체와의 협의가 필요하다.
- 출처: 덴트웹 FAQ(가입 방법·요금·아이디 4개), 맥가이·맥시웹·팅커뷰 가입 안내(CP코드 방식), 데이터넷 2012년 기사(API 개방·수익 배분). 주소는 이 문서 맨 아래.

## 4. 연동 방식 (KT 가이드 확인 후 하나로 확정) [가정]
| 방식 | 조건 | 내용 |
|---|---|---|
| **A. 서버 연동 (우선)** | KT 가 서버에서 부를 수 있는 REST API 를 주고 고정 IP 가 필수가 아님 | Worker 가 KT 에 발신 요청(클릭투콜), Cron(5분)으로 통화 이력을 가져와 `tm_calls` 에 저장. 인증키는 Cloudflare secret |
| **B. 중계 연동** | 고정 IP 필수 또는 PC 설치 프로그램 전용 | 사무실 PC(또는 소형 서버)에 중계 프로그램을 두고 KT ↔ Worker 사이를 잇는다. 범위·비용이 커지므로 사용자 확인 필수 |
| **C. API 없이 (대안)** | API 를 못 쓰는 상품 | TM 앱은 `tel:` 링크로 전화를 걸고(통화매니저 PC 프로그램/휴대폰이 받음), 결과는 수동 입력. 통화 이력은 통화매니저에서 엑셀로 내려받아 **외부 데이터 업로드(상담·TM 결과)** 로 올린다 — 이 기능은 이미 있다 |

> C 는 지금도 거의 가능하므로, **1단계(TM 앱)를 KT API 와 무관하게 먼저 만들고** 2단계에서 A 또는 B 를 붙인다.

## 5. 설계안

### 5-1. 역할·권한
- 새 계정 역할 **`TM`** (`accounts.role`): 지정 현장의 TM 앱만 사용. 통합관리(hub)에는 못 들어온다. (계약담당·열람 역할과 같은 방식 — `server/src/core/auth.js`, `index.js` 의 roles)
- TM 계정은 **자기에게 배정된 고객만** 본다. 배정 = `customers.owner_id`. 지금 `owner_id` 는 직원(staff) id 이므로 둘 중 하나를 정해야 한다:
  - (기본안) 새 열 `customers.tm_account_id` 를 추가해 TM 계정에 배정 (영업 담당 `owner_id` 와 TM 담당을 따로 관리)
- 전화번호 원문: TM 앱에서도 목록은 가려서 보이고, **전화를 거는 순간 서버가 번호를 써서 발신**(A 방식)하면 TM 화면에 원문을 보낼 필요가 없다. C 방식은 `customer.reveal` 과 같이 열람 기록을 남긴다.
- 동의 미확인(`consent = '미확인'`)·연락 거부(`dnc = 1`)·상태 `거부` 고객은 **서버에서 발신을 거절**한다.

### 5-2. 새 표 (마이그레이션 `014_tm.sql`, 모두 `project_id` 포함)
```
tm_agents     (project_id, account_id, ext_no 내선/발신번호, kt_user_id, active)          -- TM 계정 ↔ KT 내선
tm_calls      (id, project_id, phone_hash, account_id, direction 발신/수신, started_at, duration_sec,
               result 연결/부재/통화중/실패, kt_call_id 유일, recording_ref, note_id, created_at)    -- 통화 이력 (KT 에서 가져온 원본)
tm_assign_log (project_id, phone_hash, from_account, to_account, by, at)                 -- 배정 변경 기록 (선택)
```
- `tm_calls.kt_call_id` 에 유일 색인 → 같은 이력을 두 번 가져와도 한 번만 저장 (CLAUDE.md 규칙 8).
- 통화 이력은 `customer.get` 의 이력(timeline)에 type `통화` 로 합쳐 보여 준다.
- 색인은 조회 조건에 맞춰 만들고 **실행 계획(EXPLAIN)으로 전체 훑기가 없는지 확인**한다 (2026-10-23 한도 초과의 교훈, `docs/배포가이드.md` 참고).

### 5-3. 서버 action (새 파일 `server/src/tm/`)
| action | 역할 | 내용 |
|---|---|---|
| `tm.queue` | TM | 내 배정 고객 중 연락 가능한 고객을 우선순위(재통화 약속 시각 → 등급 → 미접촉)로 |
| `tm.customer` | TM | 고객 한 명의 상세·이력 (배정된 고객만) |
| `tm.call` | TM | 발신 요청 (A: KT 호출 / C: 번호 반환 + 열람 기록). 동의·연락 거부 검사 |
| `tm.result` | TM | 통화 결과 저장 → `customer_notes`(kind TM) + 상태·등급·다음 연락 일시 |
| `tm.assign` | 관리자·보조관리자 | 고객 묶음(필터 결과)을 TM 계정에 배정/회수 (통합관리 고객 DB 화면에 버튼 추가) |
| `tm.stats` | 관리자·보조관리자 | TM 별 통화 수·연결률·결과 분포·방문 전환 |
| `tm.syncCalls` | Cron / 관리자 | KT 통화 이력 가져오기 (A 방식) |
| (웹훅) | KT | 수신 이벤트 → 수신 팝업 (KT 가 지원할 때만) |
- 다음 연락 일시: `customers.next_call_at` 열 추가(재통화 예약).
- 새 action 마다 `server/test/` 에 통합 시험 추가, `test/check-scope.mjs` 의 SCOPED 에 새 표 추가.

### 5-4. TM 앱 화면 (`web/tm/`, 순수 HTML/JS, hub 디자인 재사용)
1. 로그인 (TM 계정) → 현장 자동
2. **오늘 할 일**: 재통화 예약 / 미접촉 / 전체 배정, 진행 수
3. **고객 카드**: 이름, 가린 번호, 등급·상태, 유입 경로, 이전 이력 → **[전화 걸기]** → 결과 버튼(통화·부재·재통화·방문약속·관심없음·결번·연락 거부) + 메모 + 다음 연락 일시 → [저장 후 다음 고객]
4. (A 방식) 통화 중 표시, 통화 종료 후 통화 시간 자동 기록
5. (지원 시) 수신 팝업
- 통합관리 쪽 추가: 고객 DB 에 [TM 배정] 버튼, 고객관리 > **TM 현황**(통계) 탭.

## 6. 개발 단계 (각 단계 끝에 멈추고 보고·승인 — CLAUDE.md 작업 방식)
| 단계 | 범위 | 완료 기준 |
|---|---|---|
| **T0. 확인** | 2장 항목 수집, KT 가이드 읽고 4장 방식 확정, 이 문서 갱신 | 방식(A/B/C)과 인증·한도·IP 조건이 문서에 적힘 |
| **T1. TM 앱 (API 없이)** | 역할 `TM`, 배정(`tm.assign`), 대기열·고객 카드·결과 저장, `tel:` 발신, 통합관리 배정 버튼 | TM 계정으로 배정 고객 30명을 처리하고 결과가 고객 DB 이력에 보임. 다른 TM·다른 현장 고객은 안 보임(시험) |
| **T2. KT 연동** | `tm_agents`·`tm_calls`, 클릭투콜, 통화 이력 가져오기(Cron), 이력 합치기 | 실제 전화 1통: 화면에서 발신 → 통화 → 이력에 시간·결과가 자동으로 붙음. 같은 이력 중복 저장 없음 |
| **T3. 수신·녹취·통계** | 수신 팝업(지원 시), 녹취 연결(지원 시), TM 현황 통계 | TM 별 통화 수·연결률이 KT 통화매니저 화면의 수치와 일치 |

## 7. 지켜야 할 것 (요약)
- 인증키·비밀번호는 Cloudflare secret (`npx wrangler secret put …`) 또는 `server/.dev.vars`. 저장소·`web/` 에 넣지 않는다.
- 전화번호 원문은 응답에 넣지 않는다(가림). 원문을 주는 곳은 열람 기록(`logs`)을 남긴다.
- 운영 DB 변경은 **백업 → 마이그레이션 → 서버 배포 → 화면 푸시** 순서. 이 PC 에서는 `npx.cmd wrangler@4.149.0 …` 을 사용자가 PowerShell 로 실행한다(Claude 세션에서는 운영 배포가 막혀 있음).
- 화면 파일을 고치면 모든 `*.html` 의 `?v=` 값을 올린다.
- 프레임워크·npm 패키지 금지, 외부 라이브러리는 CDN 버전 고정.

## 8. 아직 정하지 않은 것
- KT API 의 실제 기능·인증·한도 (T0)
- TM 담당이 사내 직원인지 외부 업체인지 (계정 발급·위탁 계약)
- 녹취를 우리 화면에서 들을 필요가 있는지
- 문자(SMS/알림톡) 발송을 같이 넣을지 — 범위 밖으로 두고 필요하면 별도 단계
