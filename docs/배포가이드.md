# 배포 가이드 (Cloudflare 버전)

> 구조: 화면(`web/`)은 **GitHub Pages**, 서버(`worker/`)와 데이터는 **Cloudflare**(무료)에서 돌아갑니다.
> 서버 코드를 올리는 명령은 Claude가 대신 실행합니다. 사용자는 **가입·로그인·토큰 입력**만 하면 됩니다.

---

## 1. Cloudflare 가입 (사용자, 약 5분)
1. <https://dash.cloudflare.com/sign-up> 에서 이메일과 비밀번호로 가입합니다. (카드 등록은 필요 없습니다.)
2. 이메일로 온 인증 링크를 눌러 인증합니다.
3. **2단계 인증을 켭니다.** 오른쪽 위 프로필 → **My Profile → Authentication → Two-factor authentication**.
4. 가입이 끝나면 Claude에게 알려 주세요.

## 2. 서버 올리기 (Claude가 실행, 사용자는 클릭 1번)
Claude가 아래를 순서대로 실행합니다. 중간에 **브라우저 창이 열리면 [Allow](허용)** 만 눌러 주세요.

1. `npx wrangler@4 login` → 브라우저에서 **Allow** (Claude가 Cloudflare에 배포할 수 있게 허용)
2. D1 데이터베이스 만들기 → `wrangler.toml` 에 DB 번호 기록
3. 표(테이블) 생성: `schema.sql` 적용
4. 비밀 값 등록 (서버에서 비밀번호 해시·급여 암호화에 쓰는 값. 자동 생성)
5. 기본 설정·조직·**관리자 계정** 생성 → **초기 비밀번호가 한 번 표시됩니다. 메모하세요.**
6. 서버 배포 → `https://attendance-api.○○○.workers.dev` 주소가 나옵니다.
7. 화면의 `web/js/config.js` 에 그 주소를 넣고 GitHub에 올립니다.

> ⚠ `worker/.dev.vars` 파일에는 암호화 키가 들어 있습니다. **절대 공유·업로드하지 말고, 같은 내용을 안전한 곳(비밀번호 관리자 등)에 백업**해 두세요. 이 파일을 잃으면 저장된 급여정보와 비밀번호를 복구할 수 없습니다. (git에는 자동으로 제외됩니다.)

## 3. 텔레그램 봇 연결 (사용자, 약 5분)
1. 텔레그램 앱에서 **`@BotFather`**(파란 체크 표시) 검색 → **[시작]** → `/newbot`.
2. 봇 **이름**(예: `OO현장 호출`)과 **사용자명**(영문·숫자·밑줄, **`bot` 으로 끝나야 함**, 예: `oo_site_call_bot`)을 입력합니다.
3. 완료 메시지의 **토큰**(`123456789:AAH...` 형태)을 복사합니다.
   - ⚠ 토큰은 비밀번호와 같습니다. **채팅·메일에 붙여넣지 마세요.** 아래 4번의 터미널에만 넣습니다.
4. 이 앱의 **터미널 탭**(또는 PowerShell)에서 실행:
   ```
   cd D:\mycode\근태관리\worker
   node scripts/set-telegram.mjs
   ```
   토큰을 붙여넣고 Enter (입력이 화면에 보이지 않는 것이 정상). `웹훅 연결 완료.` 가 나오면 성공입니다.
5. 관리자 화면 **설정 > 기본 설정 > 텔레그램 봇 이름** 에 사용자명(`@` 없이)을 넣고 저장합니다.

## 3-1. 직급(팀장·본부장) 지정
1. 관리자 화면 **직원 관리** → 해당 직원 **[수정]**.
2. **직급**을 `팀장` 또는 `본부장` 으로 선택 (팀장은 소속 팀, 본부장은 소속 본부가 먼저 지정되어 있어야 하고, "영업" 직군만 가능).
3. 직원 가입을 승인·퇴사 처리할 수 있게 하려면 **승인·퇴사 처리 권한 부여**를 체크하고 저장합니다.
4. 해당 직원 앱 홈에 **[직원 승인 관리]** 버튼이 생깁니다 (팀장: 자기 팀 직원, 본부장: 자기 본부 직원·팀장).
5. 호출 때 담당 직원의 팀장·본부장이 텔레그램을 연결해 두었다면 **호출 알림**을 함께 받습니다.

## 3-2. 방명록 태블릿 설정
1. 관리자 화면 **설정 > 계정 > [+ 계정 추가]** → 역할 **방명록 (고객 입력 태블릿 전용)**, 아이디(예: `guestbook`), 비밀번호(8자 이상, 영문+숫자)를 정해 저장합니다. (이 계정은 방명록 제출만 가능하고, 직원·예약 정보는 볼 수 없습니다.)
2. 태블릿 브라우저에서 `https://kunbada.github.io/attendance/guest.html` 을 엽니다.
3. 위 계정으로 **한 번만 로그인**합니다. 30일 동안 유지됩니다. (분실 시 관리자 화면에서 그 계정을 **사용 중지**하면 즉시 쓸 수 없습니다.)
4. 크롬: 메뉴 ⋮ → **홈 화면에 추가**(또는 바로가기)로 두면 앱처럼 열립니다. 전체 화면·화면 꺼짐 방지는 태블릿 설정에서 해 주세요.
5. 로그인 해제: 화면 맨 위 **제목을 3초 길게** 누릅니다 (고객이 실수로 누르지 않게 숨겨 둔 기능).
6. 고객이 입력한 내용(성명·전화번호·동행·동의)은 데스크 화면 **방명록 탭**에 "확인 필요"로 나타납니다. 성별은 고객이 입력하지 않으므로 데스크 안내직원이 [수정]에서 입력하고, **본부 → 팀 → 담당자**를 고르고(없으면 "없음", 본부 선택을 안 하면 워킹) 저장한 뒤, 줄 맨 앞 **[호출]**을 누릅니다.
7. 개인정보 동의 문구는 임시 문구입니다. **운영 전에 회사에서 확정**한 문구로 바꿔야 합니다.

## 4. 처음 사용 순서
1. **관리자:** `https://kunbada.github.io/attendance/admin.html` → `admin` + 초기 비밀번호 → **새 비밀번호로 변경**.
2. **설정:** 현장명, GPS 허용거리, 예약 중복 기준 저장. **조직**(본부·팀·직군)을 실제에 맞게 수정.
3. **설정 > 계정 > [+ 계정 추가]** 로 데스크 계정(역할 `데스크`)을 만들고 임시 비밀번호를 전달합니다. 첫 로그인 때 직접 바꿉니다.
4. **설정 > 가입 링크 QR** 을 직원에게 공유.
5. **직원:** 가입 → 관리자 승인 → 로그인 → 홈에서 **[텔레그램 연결]**.
6. **데스크:** `https://kunbada.github.io/attendance/desk.html` 을 열어 즐겨찾기.
7. **출근:** 관리자가 현장에서 **QR 생성 탭 → [오늘 QR 만들기]**(위치 허용) → 인쇄·게시 → 직원이 [출근하기].

## 5. GitHub Pages (화면 배포)
- 저장소 **Settings → Pages → Source: GitHub Actions** (이미 설정됨). `main` 에 올리면 `web/` 만 자동 배포됩니다.
- 주소: `https://kunbada.github.io/attendance/staff.html` (직원), `admin.html` (관리자), `desk.html` (데스크).

## 6. 운영·점검
- **서버 코드를 고쳤을 때:** Claude가 `npx wrangler@4 deploy` 를 실행해 반영합니다.
- **DB 구조가 바뀌었을 때:** `worker/migrations/` 의 새 파일을 한 번만 실행합니다 (Claude가 처리). 새로 만들 때는 `schema.sql` 만 실행하면 됩니다.
- **백업:** 데이터베이스 전체를 파일로 내려받기
  ```
  cd D:\mycode\근태관리\worker
  npx wrangler@4 d1 export attendance --remote --output=backup.sql
  ```
  (D1 은 최근 7일 안의 시점으로 되돌리는 기능도 있습니다.) `backup.sql` 에는 개인정보가 들어 있으니 안전하게 보관하세요.
- **관리자 비밀번호를 잊었거나 잠김 (이메일 인증, 기본 방법):** 관리자 로그인 화면의 **[비밀번호를 잊으셨나요?]** → 아이디 입력 → 계정에 등록된 이메일로 6자리 인증 코드 발송 → 코드와 새 비밀번호 입력. 코드는 10분 유효, 5번 틀리면 30분 잠금, 변경되면 이전에 로그인된 곳은 모두 로그아웃되고 알림 메일이 한 통 더 갑니다.
  - 처음 한 번 준비: ① 관리자 **설정 > 계정**에서 `admin` 의 **[수정]** → **이메일** 입력 후 저장 ② 아래 "이메일 발송 설정"을 한 번 해 두기.
- **관리자 비밀번호를 잊었는데 이메일도 쓸 수 없을 때 (서버에서 직접):** 아래를 실행하면 `admin` 의 새 임시 비밀번호가 나옵니다.
  ```
  cd D:\mycode\근태관리\worker
  node scripts/make-seed.mjs
  npx wrangler@4 d1 execute DB --remote --file=.seed.sql
  ```
- **무료 한도(하루):** 서버 요청 10만 건, DB 읽기 500만 행·쓰기 10만 행. 이 앱은 하루 1만 건 안팎이라 여유가 큽니다. 한도를 넘으면 그날은 멈추고 한국 시간 오전 9시에 풀립니다.
- **직원이 PIN 5회 실패로 잠김:** 관리자 화면 [PIN 초기화].
- **서버 로그:** Cloudflare 대시보드 → Workers & Pages → `attendance-api` → Logs. 요청마다 `action 걸린시간ms` 가 남습니다.

## 6-0. 이메일 발송 설정 (비밀번호 초기화용, 한 번만)
이메일은 무료 서비스 **Resend**로 보냅니다. 별도 도메인 없이도 되고, 이 경우 **Resend 가입 이메일 주소로만** 발송됩니다 (관리자 1명이면 충분합니다).
1. <https://resend.com> 에서 **관리자가 인증 코드를 받을 이메일**(예: `kunbada@gmail.com`)로 가입하고 이메일 인증을 합니다. (카드 등록 불필요)
2. 왼쪽 메뉴 **API Keys → Create API Key** → 이름 `attendance`, 권한 **Sending access** → **Add** → `re_` 로 시작하는 키를 복사합니다. ⚠ 키는 비밀번호와 같으니 채팅에 붙여넣지 마세요.
3. 이 앱의 터미널에서 실행하고 키를 붙여넣은 뒤 Enter:
   ```
   cd D:\mycode\근태관리\worker
   node scripts/set-resend.mjs
   ```
4. Claude에게 **"Resend 키 입력했어"** 라고 알려 주세요 (서버에 비밀 값으로 올리고 임시 파일을 지웁니다).
5. 관리자 화면 **설정 > 계정**에서 `admin` 의 **이메일**이 1번에서 가입한 주소와 **같은지** 확인합니다. (다르면 발송되지 않습니다.)
6. 로그인 화면 **[비밀번호를 잊으셨나요?]** 로 코드가 오는지 한 번 시험해 보세요.
   - 나중에 회사 도메인을 Resend에 등록하면 다른 주소로도 보낼 수 있습니다 (Claude에게 요청).

## 6-1. 운영 리허설 (하루 실제 운영 점검)
정식 운영 전날 또는 첫날, 아래 순서로 한 번 돌려 봅니다. 이상이 있으면 그 줄을 Claude에게 알려 주세요.

**전날 준비**
- [ ] 관리자 비밀번호 변경, 현장명·GPS 허용거리·예약 중복 기준 확인
- [ ] 조직(본부·팀)이 실제와 같은지, 데스크 계정·**방명록 계정** 생성
- [ ] 개인정보 동의 문구 확정본으로 교체 (직원 가입 화면 + 방명록 태블릿) — 임시 문구 상태로 운영하지 않기
- [ ] 직원 가입 → 승인, 팀장·본부장 직급과 승인 권한 지정, 전원 텔레그램 연결 확인 (관리자 직원 목록에서 확인)
- [ ] `worker/.dev.vars` 백업, 데이터 백업 한 번 실행 (6장)
- [ ] 데스크 PC·태블릿에서 `desk.html`, 방명록 태블릿에서 `guest.html` 로그인해 두기

**당일 아침**
- [ ] 현장에서 QR 생성·인쇄·게시
- [ ] 직원 몇 명이 출근 → 대시보드 출근 숫자 확인, 200m 밖·다른 폰 시도가 막히는지 한 번 확인

**영업 시간 중**
- [ ] 예약 → 데스크 예약검색 → 호출 → 직원 [확인] → "확인함" (속도 체감도 확인)
- [ ] 방명록 태블릿 입력 → 데스크 [확인 필요] → 성별·담당자 입력 → 호출
- [ ] 텔레그램 미연결 직원 호출 시 전화번호 안내 확인
- [ ] 팀장·본부장이 `[호출 알림]`을 받는지, 가입 승인·퇴사 처리가 되는지

**마감 후**
- [ ] 대시보드의 숫자(출근·예약·방문·방명록)가 실제와 맞는지
- [ ] 근태·예약·방문·방명록 CSV를 내려받아 엑셀에서 한글 깨짐 없이 열리는지
- [ ] 불편했던 점·느렸던 점·헷갈린 문구 메모

## 7. 체크리스트
