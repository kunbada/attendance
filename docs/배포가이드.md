# 배포 가이드 (1단계: 기반)

> 구글 계정은 **관리자 본인 계정**으로, 2단계 인증을 켜 둔 상태에서 진행하세요.
> 코드를 고칠 때마다 아래 "코드를 바꿨을 때" 순서를 다시 해야 반영됩니다.

## A. 서버 만들기 (Apps Script) — 약 15분

### A-1. 프로젝트 만들고 코드 붙여넣기
1. 브라우저에서 <https://script.google.com> 에 접속 → 관리자 구글 계정으로 로그인.
2. 왼쪽 위 **[새 프로젝트]** 클릭. 위쪽의 "제목 없는 프로젝트"를 눌러 이름을 `근태관리` 로 바꿉니다.
3. 왼쪽 톱니바퀴 **[프로젝트 설정]** → **"'appsscript.json' 매니페스트 파일을 편집기에 표시"** 체크 → 다시 왼쪽 **[편집기]**(`< >` 아이콘)로 돌아옵니다.
4. 왼쪽 파일 목록에 `코드.gs`(또는 `Code.gs`)와 `appsscript.json` 이 보입니다.
5. 이 폴더의 `apps-script/` 안 파일을 하나씩 엽니다. 파일마다 아래를 반복합니다.
   - `Code.gs` → 편집기의 `코드.gs` 를 열어 **내용 전체를 지우고** `Code.gs` 내용을 붙여넣기. (파일 이름은 그대로 두어도 됩니다.)
   - `appsscript.json` → 편집기의 `appsscript.json` 내용 전체를 지우고 붙여넣기.
   - 나머지 `Auth.gs`, `Sheets.gs`, `Staff.gs`, `Admin.gs`, `Setup.gs`, `Tests.gs` → 파일 목록 위 **[+]** → **스크립트** → 이름을 `Auth` 처럼 (`.gs` 는 자동) 입력 → 기본으로 들어 있는 `function myFunction() {}` 를 지우고 내용 붙여넣기.
6. 맨 위 **[저장]**(디스크 아이콘) 클릭.

### A-2. 최초 설정 실행 (시트 자동 생성)
1. 위쪽 함수 선택 칸(▶ 실행 옆)에서 **`setup`** 선택 → **[실행]**.
2. "승인 필요" 창이 뜨면 **[권한 검토]** → 본인 구글 계정 선택 → "Google에서 확인하지 않은 앱" 화면에서 **[고급]** → **[근태관리(안전하지 않음)으로 이동]** → **[허용]**. (내가 만든 코드라 나오는 정상 화면입니다.)
3. 아래 **실행 로그**에 다음이 나오면 성공입니다. **메모해 두세요.**
   - 시트 A, 시트 B 주소 (내 구글 드라이브에 `근태관리_A_운영데이터`, `근태관리_B_급여정보(공유금지)` 두 파일이 생깁니다.)
   - 관리자 아이디 `admin` 과 **초기 비밀번호**
4. 구글 드라이브에서 **시트 B 파일은 절대 공유하지 마세요** (주민번호·계좌가 들어갑니다).

### A-3. 동작 확인 (배포 전, 편집기에서)
1. 함수 선택 칸에서 **`test_stage1`** → **[실행]**.
2. 실행 로그에 `=== 1단계 테스트 전체 통과 ===` 가 나오면 서버 로직이 정상입니다. `[실패]` 줄이 있으면 그 줄을 알려 주세요.
   (테스트용 가짜 직원은 끝나면 자동으로 지워집니다.)

### A-4. 웹앱으로 배포
1. 오른쪽 위 **[배포]** → **[새 배포]**.
2. 톱니바퀴(유형 선택) → **[웹 앱]**.
3. 설정: 설명 `v1` / 다음 사용자 인증 정보로 실행: **나** / 액세스 권한이 있는 사용자: **모든 사용자**.
4. **[배포]** → 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/....../exec`)을 복사합니다.
   - 이 주소가 공개되어도 로그인 없이는 데이터를 볼 수 없게 서버에서 막혀 있습니다.
5. 복사한 URL을 저에게 알려 주시면 `web/js/config.js` 에 넣어 드립니다. (직접 하려면 그 파일의 `API_URL` 값을 바꾸면 됩니다.)

### 코드를 바꿨을 때 (매번)
편집기에 바뀐 파일을 붙여넣고 저장 → **[배포] → [배포 관리] → 연필(수정) → 버전: "새 버전" → [배포]**.
(새 배포를 또 만들면 URL이 바뀌니 꼭 "배포 관리"에서 새 버전으로 올리세요.)

## B. 내 PC에서 화면 미리 보기 — 약 5분

카메라·GPS는 HTTPS 또는 `localhost` 에서만 동작합니다. 1단계에는 카메라·GPS가 없지만, 같은 방식으로 확인합니다.

1. `config.js` 에 웹앱 URL을 넣은 뒤, 터미널에서 이 프로젝트 폴더로 이동해 실행:
   ```
   npx serve web
   ```
2. 브라우저에서 `http://localhost:3000/admin.html` (관리자), `http://localhost:3000/staff.html#signup` (직원 가입).
3. 관리자: 아이디 `admin` + 초기 비밀번호로 로그인 → **새 비밀번호로 변경** → 직원 관리 화면.

## C. 폰으로 확인하려면 (GitHub Pages)

폰에서 접속하려면 HTTPS 주소가 필요합니다. `.github/workflows/pages.yml` 이 `web/` 폴더만 자동 배포합니다.

1. <https://github.com/new> 에서 저장소 생성: 이름 예) `attendance`, **Public** 선택 (무료 계정은 공개만 Pages 가능), README 등은 체크하지 않음.
2. 이 프로젝트 폴더를 그 저장소에 올립니다 (Claude에게 "깃허브에 올려줘"라고 하면 대신 해 드립니다).
3. 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 선택.
4. 위쪽 **Actions** 탭에서 `Deploy web to GitHub Pages` 가 초록색 체크가 되면 완료.
5. 주소: `https://내아이디.github.io/저장소이름/staff.html` (직원), `.../admin.html` (관리자).

## 문제가 생기면
- **관리자 비밀번호를 잊었거나 5회 실패로 잠김**: 편집기에서 `resetAdminPassword` 실행 → 로그에 새 비밀번호가 나옵니다.
- **직원이 PIN을 5회 틀려 잠김**: 관리자 화면에서 그 직원의 [PIN 초기화].
- **"서버 설정이 끝나지 않았습니다"**: `setup` 을 실행하지 않았거나 다른 프로젝트에 배포한 경우입니다.

# 2단계: 근태 (QR 출근)

## 서버 반영 (Apps Script) — 순서대로
1. 편집기에서 **새 파일 `Attendance`** 를 만들어(**[+] → 스크립트**) `apps-script/Attendance.gs` 내용을 붙여넣습니다.
2. 아래 4개 파일은 **내용을 지우고 다시 붙여넣기** 합니다: `Code.gs`, `Staff.gs`, `Admin.gs`, `Tests.gs`. 저장.
3. **권한 다시 허용 (1회):** 출근 셀카를 구글 드라이브에 저장하려고 드라이브 권한이 추가로 필요합니다. 함수 선택에서 **`test_stage2`** 를 **[실행]** → "권한 검토" 창이 뜨면 이전처럼 **[고급] → [이동] → [허용]**.

5. **[배포] → [배포 관리] → 연필 → 버전 "새 버전" → [배포]** (주소는 그대로 유지됩니다).

# 3단계: 예약 · 데스크 · 텔레그램 호출

## A. 텔레그램 봇 만들기 (무료, 약 5분)
1. 폰이나 PC의 **텔레그램 앱**에서 검색창에 `BotFather` 를 검색해 **파란 체크 표시가 있는** `@BotFather` 를 엽니다.
2. **[시작]**(Start) → `/newbot` 이라고 보냅니다.
3. 봇 **이름**(화면에 보이는 이름, 예: `OO현장 호출`)을 입력합니다.
4. 봇 **사용자명**을 입력합니다. 영문·숫자·밑줄만 가능하고 **반드시 `bot` 으로 끝나야** 합니다 (예: `oo_site_call_bot`). 이미 쓰는 이름이면 다른 이름을 시도하세요.
5. 완료 메시지에 `Use this token to access the HTTP API:` 아래 긴 문자열이 **토큰**입니다. 복사해 두세요.
   - ⚠ **토큰은 비밀번호와 같습니다.** 카톡·메일·채팅에 붙여넣거나 이 프로젝트 폴더·GitHub에 적지 마세요. 아래 2번 칸에만 넣습니다.
   - 유출되었다면 BotFather 에서 `/revoke` 로 새로 받을 수 있습니다.

## B. 서버(Apps Script) 반영 — 순서대로
1. **새 파일 3개**를 만듭니다 (**[+] → 스크립트**): `Reservation`, `Visit`, `Telegram`. 각각 `apps-script/` 의 같은 이름 파일 내용을 붙여넣습니다.
2. 아래 파일은 **내용을 지우고 다시 붙여넣기** 합니다: `Code.gs`, `Staff.gs`, `Setup.gs`, `Tests.gs`. 저장.
3. 왼쪽 **⚙ 프로젝트 설정** → 맨 아래 **스크립트 속성** → **[스크립트 속성 추가]** 로 2개를 넣습니다.
   - 속성 `TELEGRAM_TOKEN` / 값: A-5 에서 복사한 토큰
   - 속성 `WEBAPP_URL` / 값: 웹앱 주소 (`https://script.google.com/macros/s/.../exec`)
   - **[스크립트 속성 저장]**
4. 함수 선택에서 **`test_stage3`** 실행 → `=== 3단계 테스트 전체 통과 ===` 확인. (실제 텔레그램으로는 아무것도 보내지 않습니다.)
5. **`setTelegramWebhook`** 실행 → 외부 서비스 접속 권한이 새로 필요하니 **[권한 검토] → [고급] → [이동] → [허용]**. 실행 로그에 `"ok":true` 가 나오면 성공입니다.
6. **`test_telegramInfo`** 실행 → 로그에 `봇 이름: @xxxx_bot` 과 `웹훅 등록: 됨` 확인. (`마지막 오류: 302` 는 구글 서버 특성상 나올 수 있고 정상입니다.)
7. **[배포] → [배포 관리] → 연필 → 새 버전 → [배포]**.

## C. 화면 반영 후 설정
1. GitHub 자동 배포가 끝나면 `admin.html` 새로고침 → **설정 > 기본 설정**:
   - **텔레그램 봇 이름**: B-6 의 `xxxx_bot` (@ 없이) → 저장
   - **예약 중복 기준**: `뒤5자리` 또는 `뒤5자리 + 성별` 선택 → 저장
2. **설정 > 계정 > [+ 계정 추가]** 로 데스크 계정을 만듭니다 (역할 `데스크`, 임시 비밀번호). 데스크 담당자는 첫 로그인 때 비밀번호를 바꿉니다.
3. 데스크 PC·태블릿에서 `https://kunbada.github.io/attendance/desk.html` 을 열고 즐겨찾기에 추가합니다.

## D. 사용법
- **직원:** `staff.html` 홈 → **[텔레그램 연결]** → 텔레그램이 열리면 **[시작]** → "연결되었습니다" → 앱으로 돌아와 새로고침하면 "연결됨". **[고객 방문 예약]** 에서 뒤 5자리·방문일 등록, 탭에서 수정·취소.
- **데스크:** 큰 숫자판에 고객 뒤 5자리 입력 → 오늘 예약이 뜨면 **[담당 ○○ 호출]**. 예약이 없고 고객이 직원 이름을 말하면 **[직원 찾기]**, 둘 다 없으면 **[담당 없음으로 기록]**. 아래 목록은 15초마다 자동 갱신되고, 3분 넘게 확인이 없으면 빨간색 "미확인" + **[재호출]**.
- **텔레그램 미연결 직원**은 호출 대신 화면에 **휴대폰 번호가 크게** 표시됩니다.
- **관리자:** **예약·방문** 탭에서 기간·본부·팀·직원 필터와 CSV.
