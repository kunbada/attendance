# 상담고객 앱 · 상담고객 탭 — 구성과 다음 단계 계획

작성 2026-11-13. 다른 모델·작업자가 이어받을 때는 `CLAUDE.md` → `docs/통합구성안.md` → 이 문서 순서로 읽는다.

## 1. 지금 만든 것 (1차)

### 1-1. 상담고객 앱 (`web/counsel.html`, `web/js/counsel.js`, `web/css/counsel.css`)
- 데스크탑 기준 화면. 상담사가 PC 에서 쓴다.
- **로그인**: 출근 앱과 같은 휴대폰 번호 + PIN → 맞으면 직원의 **텔레그램으로 6자리 인증번호**(5분, 5회 틀리면 무효, 1분에 한 번만 재발송) → 입력하면 로그인(세션 종류 `counsel`, 12시간).
  - 텔레그램이 연결되지 않은 직원은 로그인할 수 없다(출근 앱에서 먼저 연결).
  - `counsel` 세션은 직원 앱 기능(출근 등)을 부를 수 없다(역할이 다름). 기기(휴대폰) 확인 대신 텔레그램 인증을 거친다.
  - 쓸 수 있는 직군: 통합관리 > 인사관리 > 조직관리 > 직원 앱 메뉴의 **"상담고객 앱"** 체크. 기본은 이름에 "상담"이 들어간 직군만 켜져 있다. 끄면 이미 로그인한 세션도 막힌다.
- **신규 상담**: 휴대폰·이름·개인정보 동의 / 관심 평형(버튼, 여러 개, 직접 입력 가능 — 계약앱의 타입 목록, 없으면 59·74·84·100㎡ 이상) / 등급 A~D / 청약 순위(특별공급·1순위·2순위·무순위·미정) + 특공 종류(신혼부부·생애최초·다자녀·노부모부양·신생아·청년·기관추천) / 상담 방식(방문·전화·문자·기타) + 상담 내용.
  - 번호를 넣으면 이미 있는 고객인지 바로 보여 준다(담당 상담사, 경로).
- **나의 고객**: 내가 담당이거나 상담 기록을 남긴 고객. 전체·내 담당·중복·담당 없음, 등급·순위 필터. 줄을 누르면 상세(정보 수정, 상담 기록 추가·내 기록 삭제, 전체 이력 = 상담·설문·방문·부동산·계약).
- **나의 부동산업소**: 내가 조사했거나 담당인 중개업소. 조사 이력(조사한 상담사), 상담 기록, 담당 포기·받기. [부동산 조사하기]는 조사 화면을 새 창으로 연다.
- **중복·담당 넘기기 규칙**
  - 고객(또는 업소)마다 담당 상담사는 한 명(`customers.owner_id`).
  - 다른 상담사가 담당 중인 고객을 저장하면 고객 정보는 바꾸지 않고 **상담 기록만** 남긴다 → 두 상담사 모두의 목록에 "중복"(다른 상담사 이름)으로 보인다.
  - 담당 상담사가 **[담당 포기]** → 다른 상담사가 **[담당 받기]**. 관리자는 통합관리 고객 상세에서 담당을 바로 바꿀 수 있다. 포기·받기는 이력에 남는다.
  - 담당이 아닌 상담사는 그 고객의 정보·이력을 볼 수 없고(이름·담당만), 상담 기록은 남길 수 있다.

### 1-1b. 관심 타입 (2026-11-13 추가)
- 프로젝트 > 주택형·세대수(`project_types`) 기준표에서 고른다. 타입군 줄마다 "84타입(미정)"과 세부 주택형(84A·84B) 버튼. 기준표에 없는 값은 저장하지 않는다.
- 설문(사전판촉)은 타입군만 묻고, 고객 DB·통계는 타입군으로 묶는다(데이터사전 5-7).

### 1-2. 부동산 조사에 조사한 직원 기록
- 조사 화면(`r/`)이 같은 브라우저에 로그인해 둔 상담고객 앱(PC) 또는 출근 앱(휴대폰, 기기키까지 확인) 토큰을 함께 보내면 서버가 확인해 `realtor_responses.staff_id` 에 남긴다. 토큰이 없거나 틀리면 빈 값(조사는 그대로 저장).
- 조사한 직원은 그 연락처의 담당이 된다(이미 담당이 있으면 그대로).

### 1-3. 데이터 (고객 DB 와 같은 표, `migrations/017_counsel.sql`)
| 무엇 | 어디에 |
| --- | --- |
| 상담고객 | `customers` (source_kind `상담`, `counsel_at`, `owner_id`=담당, `interest`=관심 평형, `subscr_rank`, `special_kind`) |
| 등급 | `customer_grades` (직접 정한 등급 — 고객 DB 자동 등급보다 우선) |
| 상담 이력 | `customer_notes` (kind `상담`, result=상담 방식, `staff_id`=상담사) |
| 로그인 인증번호 | `staff_otp` |
- 고객 DB: 경로 **"상담"**(상담 앱에서 등록했거나 상담사 기록이 있는 고객, 중개사만인 사람은 "부동산"), 위쪽 카드 "상담 고객". 홈 고객현황 "상담 고객 · 이번 달 상담".
- 통합관리 > 고객관리 > **상담고객** 탭: 상담사별 현황(담당 고객·A·B·이번 달/전체 상담), 목록(담당·등급·순위·중복 필터), 줄 → 고객 상세.

## 2. 다음 단계 (예정, 아직 만들지 않음)

### 2-1. 당첨자관리
- 청약 결과(당첨자 명단)를 올리거나 조회해서 상담하고, 상담 이력을 남긴다.
- 들어갈 것(안)
  - 당첨자 명단 올리기: 엑셀/CSV(동·호, 성명, 생년월일 일부, 연락처, 공급 구분 = 특별공급 종류/일반 1·2순위, 당첨 순번·예비 번호). 고객 DB 와 전화번호로 연결 → 상담고객이면 담당 상담사에게 바로 보임.
  - 주택소유 검색 결과 기록: 청약홈(한국부동산원)의 주택소유확인·부적격 조회 결과를 사람이 확인해 입력(적격 / 부적격 의심 / 소명 필요, 메모). **자동 조회(스크래핑)는 하지 않는다** — 공인인증·개인정보 문제로 수기 입력 + 근거 파일 첨부(필요 시 R2)를 기본으로 검토.
  - 당첨자 상담 진행 상태: 서류 안내 → 서류 접수 → 적격 확인 → 계약 예정 → 계약(계약앱 연결) / 포기·부적격.
  - 상담 이력은 지금과 같은 `customer_notes`(kind `당첨자상담`)로 남긴다.
  - 화면: 상담고객 앱에 "당첨자" 메뉴, 통합관리 상담고객 탭에 당첨자 현황(공급 구분별 계약 전환율).
- 정할 것: 당첨자 명단 원본의 개인정보 보관 기간·접근 권한, 주택소유 확인 결과를 누가 입력하는지, 예비 당첨자 순번 운영 방식.

### 2-2. 그 밖에 검토
- 상담 일정(다음 연락 예정일) 알림 — 텔레그램으로 그날 연락할 고객 목록.
- 상담고객 앱에서 방문예약 등록(현재는 출근 앱).
- 고객 목록이 수만 명이 되면 `loadCustomers`(전체를 읽어 묶음)가 무료 한도(하루 500만 행 읽기)에 부담 → 상담 앱 목록은 담당·기록 기준 질의로 바꾸기.
