# 권한표 (1단계 기준)

> 권한 확인은 **항상 서버에서** 합니다 (`server/src/core/auth.js` 의 `authenticate`, `server/src/index.js` 의 `ACTIONS` 표). 화면에서 버튼을 숨기는 것은 편의일 뿐입니다.
> 단계가 진행되면 이 표에 기능을 추가합니다 (설문·계약·지급·레포트).

## 1. 확인 순서 (모든 요청 공통)

1. **로그인(세션)** — 토큰이 유효한가
2. **역할** — 이 역할이 이 기능을 부를 수 있는가
3. **현장 범위** — 이 사용자가 요청에 적힌 현장(`projectId`)에 접근 가능한가
   - 관리자: 모든 현장
   - 보조관리자·계약담당·열람: `account_projects` 에 지정된 현장만
   - 데스크·방명록: 지정된 현장 **1개에 고정** (다른 현장을 적으면 거부)
   - 영업사원(팀장·본부장 포함): 가입한 현장 **1개** (다른 현장을 적으면 거부)
4. **(직원이면) 등록된 휴대폰(deviceKey)** 인가
5. 데이터를 읽고 쓸 때는 항상 `project_id = 이 현장` 조건을 건다. 다른 현장 직원·기록의 번호(id)를 알아내도 "찾을 수 없습니다"로만 응답한다.

## 2. 역할

| 역할 | 로그인 | 범위 | 지금 쓸 수 있는 화면 |
| --- | --- | --- | --- |
| 관리자 | 아이디+비밀번호 | 모든 현장 | 통합관리(hub) 전체 |
| 보조관리자 | 아이디+비밀번호 | 지정한 현장만 | 통합관리(hub): 아래 표의 ○ 항목 |
| 계약담당 | 아이디+비밀번호 | 지정한 현장만 | 아직 없음 (4단계 계약 연동에서) |
| 열람 | 아이디+비밀번호 | 지정한 현장만 | 아직 없음 (6단계 레포트에서). 시행사 등 외부 보고용 |
| 데스크 | 아이디+비밀번호 | 현장 1개 고정 | `desk.html` |
| 방명록 | 아이디+비밀번호 | 현장 1개 고정 | `guest.html` (고객 입력 태블릿) |

| 영업사원 | 휴대폰+PIN | 본인 | `staff.html` |

보조관리자에게는 관리자가 계정마다 두 가지를 **추가로 허용**할 수 있습니다 (기본은 둘 다 불가).
- `급여정보 원문 보기` — 주민번호·계좌 원문 (열람할 때마다 `logs` 에 기록)
- `지급 확정` — 2단계 지급 기능에서 사용

## 4. 현장 이동·접근 변경이 반영되는 때

- 보조관리자의 담당 현장을 바꾸면 **다음 요청부터 바로** 적용됩니다 (서버가 매 요청마다 확인).
- 직원을 다른 현장으로 이동하면 그 직원의 로그인이 풀립니다. 다시 로그인하면 새 현장으로 들어갑니다.
- 계정을 사용 중지하거나 비밀번호를 새로 정하면 그 계정으로 로그인된 곳이 모두 풀립니다.

## 5. 시험으로 확인하는 것

`server/test/run.mjs` (통합 시험)
- 보조관리자 A 가 B 현장의 직원 목록·승인·반려·퇴사·PIN 초기화·급여정보·수정을 시도하면 거부
- 관리자라도 A 현장 화면에서는 B 현장 직원 번호로 아무것도 못 함
- 데스크·방명록 계정이 다른 현장을 가리키면 거부, 다른 현장의 방명록·방문·예약을 수정/삭제/호출하면 거부
- 직원이 다른 현장을 가리키면 거부, 같은 뒤 5자리 예약도 현장이 다르면 별개
- 보조관리자는 계정·프로젝트·설정·현장 이동 같은 관리자 전용 기능을 부르면 거부
- 급여 원문은 허용되지 않은 보조관리자에게 거부, 허용돼도 자기 현장 직원만, 기록이 남음

`server/test/check-scope.mjs` (서버를 띄우지 않고 소스를 훑는 점검)
- 현장 표를 읽거나 바꾸는 SQL 에 `project_id` 조건이 빠진 곳이 있으면 실패합니다. 일부러 현장과 무관하게 다루는 곳(휴대폰 번호로 사람 찾기, 텔레그램 웹훅 등)은 파일 안에 이유와 함께 예외로 적혀 있습니다.
